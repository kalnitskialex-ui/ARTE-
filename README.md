# ARTE — мониторинг объявлений о недвижимости

Собирает объявления с площадок (ЦИАН, Avito, Домклик, Яндекс Недвижимость, сайты агентств),
приводит их к единой модели, склеивает один и тот же объект с разных сайтов, хранит историю цен
и сообщает в Telegram о новых предложениях и снижении цены. Есть REST API, веб-дашборд
и выгрузка в Excel/CSV/JSON.

## Как это устроено

```
jobs.yaml ─► Crawler ─► Загрузчик ─────────► Извлечение (слоями) ─► БД ─► API / дашборд / экспорт
             выдача      httpx | Scrapling     1. правила площадки        объекты (дедуп)
             ↓ ссылки    Firecrawl | браузер   2. JSON-LD (schema.org)    история цен
             объявления                        3. встроенный JSON-стейт   события ─► Telegram
                                               4. адаптивные селекторы
                                               5. мета, пары «подпись → значение», текст
                                               6. LLM: Firecrawl JSON /
                                                  Claude / ScrapeGraphAI
```

Главная идея: **сначала дешёвые и точные методы, LLM — только когда их не хватило.**
Современные площадки отдают данные фронтенду в виде JSON прямо в HTML (`__NEXT_DATA__`,
`window._cianConfig`, URL-кодированный `__initialData__` и т.п.). ARTE находит такие блоки
без привязки к вёрстке: ищет поддерево, где сосредоточено больше всего характерных полей
(цена, площадь, комнаты, этаж, координаты), и игнорирует блоки «похожих объявлений».
Поэтому смена дизайна сайта обычно ничего не ломает, а LLM-вызовы почти не нужны.

| Модуль | Что делает |
|---|---|
| `fetch/http.py` | httpx: темп по хостам, повторы с backoff и `Retry-After`, robots.txt, условные запросы (ETag/304), остановка при защите от ботов |
| `fetch/scrapling_backend.py` | Scrapling: `http` (curl_cffi) или `dynamic` (Playwright) |
| `fetch/firecrawl.py` | Firecrawl: рендер JS, HTML + ссылки + JSON по нашей схеме за один вызов, `map` сайта |
| `extract/structured.py` | JSON-LD, встроенный стейт, meta, пары «подпись → значение», регулярные выражения |
| `extract/pipeline.py` | Сборка слоёв и проверка правдоподобия (координаты 0/0, жилая ≥ общей и т.п.) |
| `extract/adaptive.py` | Самовосстанавливающиеся CSS-селекторы (Scrapling) |
| `extract/llm.py`, `extract/scrapegraph.py` | LLM-извлечение: Claude (structured outputs) или ScrapeGraphAI |
| `sources/` | Адаптеры площадок: шаблоны URL, ID, пагинация, точные правила |
| `analytics.py` | Рыночная оценка по аналогам (медиана ₽/м²), поиск предложений ниже рынка, события `good_deal` |
| `dedup.py` | Склейка дублей: комнаты + этаж + площадь ±2 % + (координаты ≤ 60 м или похожий адрес) |
| `storage/` | SQLAlchemy (SQLite/PostgreSQL): объекты, объявления, история цен, события |
| `api/` | FastAPI + дашборд (таблица, фильтры, карта, график цены, дубли на других сайтах) |

## Быстрый старт

```bash
uv venv && uv pip install -e ".[all,dev]"     # или: pip install -e ".[all,dev]"
cp .env.example .env                         # настройте загрузчик и ключи
cp jobs.example.yaml jobs.yaml               # вставьте свои ссылки поиска

arte check "https://..."     # разобрать одно объявление и показать результат (без записи в БД)
arte crawl                   # один проход по всем заданиям
arte run                     # работать постоянно по расписанию заданий
arte serve                   # API и дашборд: http://127.0.0.1:8000
arte export out.xlsx --deal-type sale --price-max 20000000
```

Docker с PostgreSQL: `docker compose up -d` (API на `:8000` + фоновый сборщик).
Для браузерных режимов один раз выполните `playwright install chromium`.

| `POST /api/jobs/{name}/run` | Запустить задание сейчас |

## Firecrawl, Scrapling, ScrapeGraphAI: что мощнее

Короткий ответ: **ни один инструмент не лучше остальных во всём. Они решают разные задачи,
поэтому все три встроены как взаимозаменяемые слои.** Выбор — настройками
`ARTE_FETCH_BACKEND` и `ARTE_LLM_BACKEND`.

| | Firecrawl | Scrapling | ScrapeGraphAI |
|---|---|---|---|
| Что это | Облачный API (можно развернуть у себя, AGPL) | Локальная библиотека (BSD-3) | LLM-конвейеры на LangChain (MIT) |
| Сильная сторона | Рендер JS без своей инфраструктуры; HTML, ссылки и JSON по схеме за один вызов; `map` всего сайта | Скорость, бесплатно; **адаптивные селекторы**, которые находят элемент после смены вёрстки | Извлечение по описанию на естественном языке, любой провайдер LLM, включая локальный Ollama |
| Слабая сторона | Платно по кредитам, JSON-извлечение дороже; данные идут через третью сторону | Селекторы нужно задать один раз; браузерный режим требует Chromium | Медленно и дорого на каждую страницу, недетерминированно, тяжёлые зависимости (LangChain) |
| Роль в ARTE | Загрузчик для сайтов на JS и запасное LLM-извлечение | Основной локальный загрузчик + адаптивные селекторы для сайтов агентств | Альтернатива Claude для страниц без структурированных данных |

Рекомендация по умолчанию:

1. **Крупные площадки** — `httpx` или `scrapling` (http): данные и так лежат во встроенном JSON,
   разбор бесплатный и точный.
2. **Сайты на JavaScript** — `firecrawl` (без инфраструктуры) или `scrapling` (`dynamic`).
3. **Сайты агентств и застройщиков с нестандартной вёрсткой** — `selectors` в `jobs.yaml`
   (Scrapling сам «чинит» их при редизайне), а без них — LLM.
4. **LLM** — Claude по умолчанию (строгая схема, ответ проверяется); ScrapeGraphAI —
   если нужен другой провайдер или локальная модель.

Что проверено: Firecrawl — на живых страницах площадок (см. ниже); адаптивные селекторы Scrapling
реально находят цену после смены `id`/классов; `arte check` через `httpx` и `scrapling` разбирает
страницу на 100 %. Claude и ScrapeGraphAI проверены на подставных клиентах.

## Правовые рамки и что сознательно не сделано

- **Условия использования.** Пользовательские соглашения Avito и ЦИАН запрещают
  автоматизированный сбор данных. Если площадка отвечает капчей или 403, ARTE останавливает
  работу с этим хостом, а не обходит защиту. Поэтому подмена отпечатков браузера, ротация прокси
  и автоматическое решение капч (в том числе `StealthyFetcher` из Scrapling) не подключены.
- **Надёжный путь для крупных площадок** — договор с площадкой или лицензированные поставщики
  рыночных данных. Партнёрские API ЦИАН и Avito в основном дают доступ к собственным объявлениям
  партнёра, а не ко всему рынку — уточняйте условия. Новый источник подключается в `sources/`.
- **Базы данных охраняются** (ст. 1334 ГК РФ — право изготовителя базы данных): массовое
  копирование существенной части чужой базы — риск. Для аналитики собирайте то, что нужно,
  и ссылайтесь на первоисточник.
- **Персональные данные (152-ФЗ).** Имена и телефоны продавцов не извлекаются: этих полей нет
  в схеме, и LLM явно запрещено их брать.
- **Вежливость:** честный User-Agent, robots.txt, пауза между запросами к хосту (по умолчанию 3 с),
  условные запросы, чтобы не скачивать неизменившиеся страницы.

## Проверка на живых площадках (октябрь 2026, через Firecrawl)

| Площадка | Ссылки в выдаче | Страница объявления | Результат разбора |
|---|---|---|---|
| Домклик | шаблон подходит (в т.ч. поддомены городов) | открылась | **100 %** ключевых полей на 2 объявлениях: цена, площадь, комнаты, этаж/этажность, год, адрес, координаты |
| Яндекс Недвижимость | шаблон подходит (в т.ч. `m.realty.yandex.ru`) | открылась | **100 %** на 2 объявлениях (продажа и аренда); координат на странице нет |
| Avito | **60 из 60** объявлений на странице выдачи распознаны | файрвол Avito (HTTP 439) | ARTE корректно останавливается |
| ЦИАН | — | капча (HTTP 200 + редирект на `/cian-captcha/`) | ARTE корректно останавливается |

Проверка нашла и исправила реальные отличия от тестовых страниц: Домклик размечает объявление
в JSON-LD как `Event` и кладёт объект в `location`, его стейт содержит JavaScript-`undefined`
(не строгий JSON), площадь лежит под ключом `area`; Яндекс не кладёт адрес в JSON — только
в мета-описание; площадки отдают устаревший код валюты `RUR`. Структуры этих страниц
воспроизведены в регрессионных тестах (без данных продавцов).

### Точный парсер против LLM-извлечения Firecrawl (те же живые страницы)

| Поле | Домклик: ARTE | Домклик: Firecrawl JSON | Яндекс: ARTE | Яндекс: Firecrawl JSON |
|---|---|---|---|---|
| Цена, площадь, комнаты, этажи, адрес | ✅ | ✅ | ✅ | ✅ |
| Жилая / кухня | ✅ (на сайте не указаны) | ❌ жилая = общей, кухня 0 | ✅ 25 / 19 (правило площадки) | ✅ |
| Координаты | ✅ | ❌ (0, 0) | — нет на странице | ✅ |
| Год | ✅ 2016 | ✅ | — | ❌ 2026 при сдаче в 2028 |

Поэтому LLM в ARTE только дополняет пустые поля, а его ответы проходят проверку
правдоподобия. Правдоподобную, но неверную цифру (как год 2026) правилами не поймать —
это предел LLM-извлечения, и это причина держать его последним слоем.

О сторонних «парсерах ЦИАН» (например, `cianparser`): они получают страницы через
cloudscraper, перебор прокси при капче и браузерный User-Agent, а также собирают телефоны
продавцов. Это обход защиты площадки, а не легальный доступ, поэтому в ARTE не используется.
Полезная идея оттуда — пары «подпись → значение» — реализована заново как слой разбора.

Вывод для Avito и ЦИАН: автоматический доступ к ним без договора закрыт, и это их осознанная
политика. Рабочие пути — партнёрские/лицензированные данные, либо выдача Avito как источник
ссылок и краткой информации. Новые площадки проверяйте так:

```bash
arte check "<ссылка на объявление>" -v
```

Смотрите на `extraction_methods` и «Заполненность ключевых полей». Если чего-то не хватает,
добавьте точные правила в `site_fields()` адаптера или `selectors` в задании.
